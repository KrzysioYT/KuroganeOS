# KuroganeOS Licensing

## Current licensing model

KuroganeOS uses the **KuroganeOS Source-Available License 1.0
(KSAL-1.0)** for current project revisions unless a file explicitly states
otherwise.

KSAL-1.0 is a **source-available** license. It is not an OSI-approved Open
Source license.

The controlling legal text is the repository's root [`LICENSE`](../LICENSE)
file.

## What KSAL allows by default

Without requesting additional permission, KSAL-1.0 allows:

- viewing and studying the source code;
- cloning the repository;
- private non-commercial execution;
- private non-commercial modifications;
- educational, research, testing and evaluation use that is non-commercial;
- use of GitHub's normal public-repository fork workflow for evaluating the
  project and proposing changes back to the official repository.

## What requires written permission

Unless a separate written permission or agreement says otherwise, KSAL-1.0
does **not** permit:

- commercial use;
- internal business deployment by a for-profit entity;
- sale or monetization;
- public redistribution of source or modified source outside the limited
  repository-fork workflow;
- redistribution of unofficial binaries, ISOs, installers or releases;
- rebranding KuroganeOS;
- using KuroganeOS code in another operating system, application, library,
  product or service;
- offering KuroganeOS as a hosted or managed service;
- sublicensing or relicensing KuroganeOS.

Contact the project owner for permissions outside KSAL's default scope.

## Contributions

Contributions are welcome, but the project owner must retain enough rights to
maintain the project, distribute official builds, change the licensing model,
and potentially offer separate commercial licensing.

Contributors should read:

- [`CONTRIBUTING.md`](../CONTRIBUTING.md)
- [`CLA.md`](../CLA.md)

A contribution may be refused or left unmerged until the applicable CLA has
been accepted.

## Third-party components

KSAL applies only to material for which the KuroganeOS licensor has authority
to grant KSAL rights.

Third-party files, libraries, specifications, headers, firmware, tools or other
materials remain governed by their own licenses and notices.

If a file contains its own license notice, that notice controls for that file.

## Public GitHub repository

A public GitHub repository is viewable and forkable through GitHub's platform
functionality under GitHub's own Terms of Service.

That platform-level permission is separate from the additional copyright
permissions granted by KSAL.

Keeping the source repository public therefore does not make KSAL an
OSI-approved Open Source license.

## Branding

The KuroganeOS name, logo and official-release identity are not licensed by
KSAL except for truthful nominative reference.

See [`TRADEMARKS.md`](../TRADEMARKS.md).

## Questions and special permissions

If you need rights beyond KSAL-1.0, request a separate written permission from
the KuroganeOS project owner.

Examples include:

- commercial deployment;
- commercial integration;
- redistributing a modified build;
- creating a derivative distribution;
- educational deployment outside the default permitted scope;
- incorporation of KuroganeOS source into another project.

## Legal note

This documentation explains the project's intended licensing model but does
not replace the controlling license text.

Because KSAL-1.0 is a custom license, the final production version should be
reviewed by a qualified intellectual-property lawyer before relying on it for
commercial enforcement.
