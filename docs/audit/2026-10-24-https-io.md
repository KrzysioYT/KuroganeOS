# HTTPS request and read lifecycle — 2026-10-24

> Zapis historyczny / dowód dla wskazanej rewizji. Nie jest instrukcją
> bieżącego wydania. Aktualny stan: [DEVELOPMENT_STATE.md](../../DEVELOPMENT_STATE.md).

The production TLS client returned success whenever any response bytes existed,
even if the read loop exited after 128 WANT_READ/WANT_WRITE retries. It also
accepted transport EOF without authenticated TLS close_notify. Partial data can
therefore no longer be mistaken for successful transport completion: exhaustion
returns Timeout; unclean EOF or a TLS read error returns IoFailure. Partial bytes
remain diagnostic output. Successful non-empty reads require close_notify, in
accordance with the pinned Mbed TLS `ssl.h` read contract. A peer omitting that
alert now fails instead of being accepted silently; this compatibility change
is intentional. HTTP Content-Length/chunk framing is still the caller's concern.

Request construction runs before session allocation or network activity. The
bounded builder accepts ASCII DNS/IPv4 host text and an origin-form escaped URI,
rejecting whitespace, control bytes, non-ASCII raw bytes, URI fragments, and host
header separators. It checks complete request capacity before writing output.
Percent-encoded path/query bytes remain unchanged. The prior profile limits
(253-byte host, 1024-byte path, 768-byte request buffer) remain in force. SNI and
certificate validation are unchanged; this does not add TLS 1.3.

The host regression includes the production client and substitutes only TLS read
and log functions. It covers fragmented success, partial timeout, empty timeout,
unclean EOF, read error, empty close, capacity overflow, header/request injection,
exact-capacity construction and input bounds. Optimized and UBSan runs and the
release kernel build pass. These are I/O-policy tests, not cryptographic handshake
or Internet interoperability qualification. Focused CI and the host suite include
the test; full network runtime qualification remains required.
