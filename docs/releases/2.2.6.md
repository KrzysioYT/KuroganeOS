# KuroganeOS 2.2.6 — macOS FAT32 runtime hotfix

Data: 2026-08-16

## Problem

Development IMG zbudowany na macOS w 2.2.5 poprawnie przechodził przez UEFI,
AHCI i GPT, ale kernel zatrzymywał wymagane testy na:

```text
[WARN][VFS][CPU0][KERNEL] FAT32 root mount failed
[WARN][VFS][CPU0][KERNEL] ok
[TEST] fat32_vfs_read: FAIL
[TEST] ALL_REQUIRED_TESTS_PASSED: FAIL
```

GPT i urządzenie blokowe były poprawne. Problem znajdował się na granicy
hostowego buildera FAT32 i rygorystycznej walidacji FAT32 KuroganeOS.

## Zmiany

- dodano `scripts/normalize-fat32.py`;
- macOS Foundation builder synchronizuje wszystkie włączone kopie FAT;
- backup BPB otrzymuje tę samą geometrię co primary BPB;
- `fsck.fat -n` nadal jest wykonywany po normalizacji;
- przed publikacją IMG builder kompiluje i uruchamia
  `tests/test_root_volume_image.cpp` na pełnym obrazie GPT;
- obraz trafia do `dist/` dopiero po udanym odczycie persistent root przez
  projektowy kod GPT/PartitionDevice/FAT32/VFS;
- hostowy test działa także na Apple Silicon — spin wait używa `yield` na ARM64
  i `pause` na x86-64;
- `root_volume` zapamiętuje prawdziwy status `fat32::mount`, więc kolejny błąd
  nie będzie już raportowany jako `FAT32 root mount failed` + `ok`.

## Oczekiwany build marker

Przed utworzeniem finalnego IMG macOS build powinien pokazać:

```text
[macos] validating Foundation image through KuroganeOS FAT32/VFS...
Foundation root PartitionDevice/FAT32/VFS read: PASS
[macos] Foundation root FAT32/VFS validation: PASS
```

Dopiero potem publikowany jest:

```text
dist/KuroganeOS-2.2.6-macos-qemu.img
```

## Build + QEMU

```bash
git pull origin main
./scripts/build-macos.sh --configuration debug --rebuild
./scripts/run-qemu-macos.sh --display
```

Build release z ISO:

```bash
./scripts/build-macos.sh --configuration release --rebuild --iso
```
