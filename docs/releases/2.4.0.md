# KuroganeOS 2.4.0 — Flux Window Core

KuroganeOS 2.4.0 rozpoczyna drugi etap roadmapy desktopu. Celem tej wersji
jest przebudowa samego WindowManagera tak, aby Kurogane Flux nie był tylko
warstwą kolorów na starym modelu pulpitu.

## Zrealizowane w 2.4.0

- WindowManager nie renderuje już klasycznego taskbara;
- usunięto tekstowe kontrolki `-`, `[]` i `X` z głównej ścieżki WM;
- dodano geometryczne kontrolki Flux: minimize, expand/restore i dismiss;
- dodano dynamiczny `Signal Spine`, który pokazuje realny z-order i focus;
- dodano pływający `Pulse Ribbon` z aktywnymi/minimalizowanymi powierzchniami;
- kliknięcie elementu Pulse Ribbon fokusuje albo przywraca okno;
- maximize korzysta z jawnego `work_area`, a nie z pełnego ekranu pomniejszonego
  o magiczną wysokość taskbara;
- drag jest ograniczony do przestrzeni roboczej Flux;
- dodano `WorkspaceGeometry` i `ChromeGeometry` jako jedno źródło prawdy dla
  renderingu, hit-testów i przyszłego resize;
- zarezerwowano i renderuje się dolny prawy resize grip; interakcja resize
  pozostaje zaplanowana na 2.7;
- test WindowManagera obejmuje geometrię workspace, chrome, Pulse Ribbon,
  minimize/restore, drag, expand i Alt+F4.

## Język wizualny

2.4 utrzymuje założenie, że KuroganeOS nie kopiuje Windows, macOS ani popularnych
desktop environments. Okno nie używa klasycznego paska tytułu z trzema
tekstowymi przyciskami. Stan sesji jest rozłożony pomiędzy:

- `Signal Spine` — pionową warstwę aktywności;
- powierzchnię okna z sygnałową krawędzią focusu;
- geometryczny control rail;
- `Pulse Ribbon` — pływającą, dynamiczną powierzchnię aktywnych aplikacji.

## Zachowana funkcjonalność

Nadal działają istniejące mechanizmy:

- generation-checked WindowId;
- z-order;
- focus;
- drag;
- minimize;
- maximize / restore;
- close;
- Alt+Tab;
- Alt+F4;
- routing inputu do procesu będącego właścicielem okna.

## Następne prace 2.4.x

Pierwszy patch 2.4 koncentruje się na WindowManagerze. W dalszej części serii
2.4.x należy jeszcze:

1. usunąć z bootloadera ostatnie komunikaty `DESKTOP ALPHA`;
2. ujednolicić wybór `desktop/console/safe/diagnostics` już na poziomie UEFI;
3. usunąć legacy `ui::taskbar()` z pozostałych diagnostycznych Ring-0 surfaces;
4. rozszerzyć runtime smoke test o interakcję Pulse Ribbon i control rail;
5. sprawdzić pełny build/QEMU na macOS oraz Windows/WSL.

## Testowanie na macOS

```bash
./scripts/build-macos.sh --configuration debug --rebuild
./scripts/run-qemu-macos.sh --image ./dist/KuroganeOS-2.4.0-macos-qemu.img --display
```

Pełny build nie został wykonany w środowisku autora patcha, ponieważ bieżący
runner nie ma dostępu DNS do GitHub ani lokalnego toolchainu użytkownika. Wersję
należy traktować jako wymagającą świeżego runtime smoke testu na docelowym Macu.
