# KuroganeOS 2.4.1 — Flux Flicker Hotfix

2.4.1 naprawia agresywne miganie framebufferowego pulpitu obserwowane w 2.4.0.
Problem nie leżał w QEMU ani w firmware UEFI. Wynikał z modelu repaintu.

## Przyczyna

W 2.4.0 działały jednocześnie trzy kosztowne ścieżki:

1. `flux_session_tick()` co 10 ticków PIT wywoływał `windowing::invalidate()`;
2. Ring-3 System Monitor wykonywał `kui_present()` co 10 ticków;
3. każdy repaint WindowManagera zaczynał się od `ui::desktop()`, a ta funkcja
   czyści cały framebuffer przed narysowaniem kolejnej klatki.

Przy braku backbuffera QEMU skanował framebuffer również w trakcie programowego
rysowania. Użytkownik widział więc fazę `clear -> ponowne rysowanie okien` jako
regularne miganie całego pulpitu.

Dodatkowo ruch myszy oznaczał pełny repaint, ponieważ każda zmiana pozycji
software cursor ustawiała globalny dirty flag.

## Naprawa

- usunięto okresowe wymuszone `invalidate()` z `flux_session_tick()`;
- WindowManager rozróżnia teraz `Content` i `Full` dirty state;
- zwykłe `windowing::invalidate()` oznacza repaint treści bez czyszczenia całego
  workspace;
- pełne czyszczenie pozostaje dla zmian strukturalnych, takich jak create,
  close, focus, minimize, maximize/restore i move;
- software cursor nie wymaga repaintu desktopu: jest odwracalnie nakładany
  bezpośrednio na GOP framebuffer przez XOR RGB;
- System Monitor został ograniczony do jednej aktualizacji na około sekundę;
- usunięto stare `DESKTOP ALPHA` z Ring-3 About;
- wersja produktu została podbita do 2.4.1.

## Oczekiwany efekt

Przy nieruchomym desktopie framebuffer pozostaje stabilny. System Monitor może
zmieniać progress/heartbeat bez czarnej klatki pomiędzy odświeżeniami, a zwykły
ruch kursora nie uruchamia full-frame repaintu.

Przeciąganie okna nadal jest zmianą geometrii i w 2.4.1 korzysta z pełnego
repaintu. Damage tracking dla geometrycznych zmian okna pozostaje kolejnym
krokiem rozwoju WindowManagera.

## Build na macOS

```bash
git pull origin main
./scripts/build-macos.sh --configuration debug --rebuild
./scripts/run-qemu-macos.sh \
  --image ./dist/KuroganeOS-2.4.1-macos-qemu.img \
  --display
```

Release IMG + ISO:

```bash
./scripts/build-macos.sh --configuration release --rebuild --iso
```

## Runtime verification

Ten hotfix został przygotowany na podstawie kodu i logiki repaintu w repo.
Pełne potwierdzenie efektu wizualnego wymaga świeżego uruchomienia QEMU na
macOS użytkownika, ponieważ bieżące środowisko autora patcha nie udostępnia
jego lokalnego Homebrew/QEMU/toolchainu.
