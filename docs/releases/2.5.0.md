# KuroganeOS 2.5.0 — Flux UI Runtime

KuroganeOS 2.5.0 rozpoczyna migrację aplikacji desktopowych z ręcznego składania
`ku_ui_frame` do userspace runtime `libui` opartego o sceny, widoki i flow layout.

## Założenie

2.5.0 celowo nie zmienia jeszcze transportowego syscall ABI `KU_SYS_UI_PRESENT`.
Najpierw aplikacje dostają stabilniejszy model programistyczny, który może być
później podłączony pod natywne widget ABI bez kolejnego przepisywania aplikacji.

## Nowe API libui

- `kui_scene` — właściciel drzewa widoków;
- `kui_view` — element z ID, parent ID, typem, flagami, tekstem i wartością;
- `kui_flow` — prosty pionowy layout oparty o kolejność widoków;
- typy: panel, label, button, input, list item, progress i separator;
- parent-child view tree;
- focus/selection traversal dla elementów interaktywnych;
- logiczne scrollowanie sceny;
- zmiana tekstu, flag i wartości widoku bez ręcznego indeksowania linii;
- zachowany kompatybilny backend `ku_ui_frame`.

## Migracja aplikacji

Na nowe API przechodzą pierwsze aplikacje systemowe:

- About;
- Settings;
- Files;
- System Monitor.

Flux Terminal pozostaje chwilowo na bezpośrednim frame API, ponieważ jego
interaktywny bufor tekstowy będzie rozwijany razem z Terminalem w 2.6.

## Dlaczego backend kompatybilny

2.4.0 ujawniło, że duże zmiany renderera wykonywane bez runtime testu mogą
spowodować regresje widoczne dopiero w QEMU. Dlatego 2.5 dzieli migrację na dwa
poziomy:

1. 2.5.0 — userspace scene/view/layout runtime;
2. 2.5.x — natywne kernelowe widget ABI, widget hit testing, wheel routing,
   dialogs/custom surfaces i dokładniejsze damage regions.

Kod aplikacji napisany pod `kui_scene` ma pozostać użyteczny po zmianie backendu.

## Build macOS

```bash
./scripts/build-macos.sh --configuration debug --rebuild
./scripts/run-qemu-macos.sh --image ./dist/KuroganeOS-2.5.0-macos-qemu.img --display
```

Problemy z instalowalnym ISO są traktowane jako osobny tor naprawy i nie blokują
rozwoju IMG/desktop runtime.
