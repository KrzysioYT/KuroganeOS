# KuroganeOS 2.5.1 — Flux framebuffer ownership hotfix

KuroganeOS 2.5.1 naprawia poważną regresję wizualną ujawnioną po migracji
aplikacji na Flux UI Runtime 2.5.0.

## Przyczyna

Boot/emergency terminal i Flux Desktop korzystały z tego samego GOP framebufferu.
`KU_SYS_WRITE` kierował stdout/stderr procesów Ring 3 przez `terminal::put()`. Po
uruchomieniu desktopu terminal nadal:

- rysował znaki bezpośrednio na framebufferze;
- przesuwał swój logiczny kursor;
- po dojściu do dolnej krawędzi wywoływał `graphics::scroll_up()`.

W rezultacie logi `[TEST]`, stdout PID1 i aplikacji GUI mogły fizycznie przesuwać
cały wyrenderowany pulpit. WindowManager następnie dorysowywał powierzchnie w
oryginalnych pozycjach, co powodowało powielone paski okien, Pulse Ribbon,
tekstowe śmieci i narastające artefakty.

`graphics::scroll_up()` samo w sobie działało prawidłowo; błędem było pozostawienie
terminalowi prawa do modyfikowania GOP podczas aktywnej sesji graficznej.

## Naprawa

- terminal dostał jawne `set_framebuffer_output(bool)`;
- serial pozostaje aktywny niezależnie od właściciela framebufferu;
- po starcie Flux Desktop terminal przechodzi w tryb serial-only;
- stdout/stderr i test markers nadal są dostępne w serial logu QEMU;
- terminal nie rysuje wtedy glyphów, nie przesuwa kursora framebufferowego i nie
  może wywołać `scroll_up()`;
- po zatrzymaniu sesji Flux terminal odzyskuje framebuffer;
- System Monitor emituje marker `flux_scene_sysmon` tylko raz na życie procesu,
  zamiast ponownie po pełnym cyklu heartbeat.

## Oczekiwany efekt

Podczas działającego desktopu:

```text
kernel/userspace stdout -> serial log only
Flux WindowManager       -> GOP framebuffer
```

Nie powinny już pojawiać się:

- `[TEST]` na pulpicie;
- pionowe/poziome kopie starych okien;
- przesuwanie całego desktopu po kolejnych logach;
- narastające kopie Pulse Ribbon;
- terminalowe znaki w prawej części ekranu.

## Test macOS

```bash
git pull origin main
./scripts/build-macos.sh --configuration debug --rebuild
./scripts/run-qemu-macos.sh \
  --image ./dist/KuroganeOS-2.5.1-macos-qemu.img \
  --display
```

Instalowalne ISO pozostaje osobnym torem naprawy i nie jest częścią tego hotfixa.
