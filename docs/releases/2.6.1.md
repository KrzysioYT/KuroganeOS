# KuroganeOS 2.6.1 — Desktop Applications I

KuroganeOS 2.6.1 zaczyna etap 2.6 roadmapy: aplikacje desktopowe mają być
użyteczne na obecnym publicznym Ring-3 ABI zamiast pozostawać demonstratorami.

## Flux Terminal

Terminal został przeniesiony na `kui_scene` i dostał większą powierzchnię.
Obsługiwane są teraz między innymi:

- `help`;
- `version` / `uname`;
- `pid`;
- `pwd`;
- `cat <absolute-path>` / `read <absolute-path>`;
- `which <name>`;
- `apps`;
- `run <app>`;
- `gui <surface>`;
- `open <path|app>`;
- `jobs`;
- `wait <pid>`;
- `history`;
- `status`;
- `echo`;
- `about`;
- `clear`.

`cat/read` korzystają z publicznego `open/read/close`; `which` sprawdza realne
obrazy pod `/apps` i `/gui`, a procesy uruchamiane przez terminal są śledzone w
tabeli jobów.

Komendy wymagające nieistniejącego jeszcze publicznego VFS capability ABI
(`ls`, `stat`, `cd`, `mkdir`, `touch`, `rm`, `cp`, `mv`) są rozpoznawane, ale
jawnie raportują ograniczenie zamiast udawać powodzenie.

## Files

Files dostało nowy ekran Quick Access oparty o realny persistent VFS. Pozwala:

- wybierać pozycje klawiszami `J/K`;
- odświeżać podgląd przez `R`;
- czytać `/etc/system.cfg` przez `open/read/close`;
- rozpoznawać obrazy ELF64;
- uruchamiać wybrane aplikacje `/gui/*` i `/apps/*` klawiszem Enter;
- podglądać wybrane pliki systemowe bez kernelowego backdoora.

Pełna enumeracja katalogów pozostaje zadaniem kolejnego 2.6.x, ponieważ VFS
ma `stat/readdir` wewnętrznie, ale publiczne Ring-3 ABI nie eksportuje ich jeszcze.

## Większy QEMU na macOS

`./scripts/run-qemu-macos.sh --display` uruchamia teraz wizualny development
path w Cocoa fullscreen z `zoom-to-fit`. Dzięki temu 1024x768-era GUI nie jest
wyświetlane jako małe okno na ekranie MacBooka.

Dostępne tryby:

```bash
./scripts/run-qemu-macos.sh --display
./scripts/run-qemu-macos.sh --windowed
./scripts/run-qemu-macos.sh --fullscreen
```

`--windowed` zachowuje skalowanie `zoom-to-fit`, ale nie wymusza fullscreen.
Testowa VM ma teraz 768 MiB RAM i jawne Standard VGA.

## Stabilność

2.6.1 zachowuje poprawkę 2.5.1: podczas aktywnej sesji Flux framebuffer należy
do desktop renderera, a kernel/userspace stdout pozostaje serial-only.

## macOS build

```bash
./scripts/build-macos.sh --configuration debug --rebuild
./scripts/run-qemu-macos.sh \
  --image ./dist/KuroganeOS-2.6.1-macos-qemu.img \
  --display
```

Instalowalne ISO pozostaje osobnym torem naprawy i nie blokuje IMG/QEMU desktop
development.
