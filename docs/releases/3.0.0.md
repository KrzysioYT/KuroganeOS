# KuroganeOS 3.0.0 — Kurogane Desktop

KuroganeOS 3.0.0 jest pierwszym wydaniem, w którym normalny boot używa
pełnoprawnego modelu sesji desktopowej zamiast automatycznego uruchamiania
wszystkich demonstracyjnych okien naraz.

## Nowy model sesji

```text
UEFI
 -> kernel
 -> persistent FAT32 root
 -> Flux Window Core
 -> /system/init PID 1
 -> /gui/launcher (Flux Home)
 -> aplikacje Ring 3 uruchamiane na żądanie
```

PID1 nadzoruje wyłącznie root sesji (`/gui/launcher`). Terminal, Files, System
Monitor, Settings i About są dziećmi Launchera. Ich normalne zamknięcie nie
powoduje już automatycznego respawnu przez PID1.

## Flux Home

Nowa aplikacja `/gui/launcher` udostępnia centralny wybór:

- Terminal;
- Files;
- System Monitor;
- Settings;
- About.

Sterowanie podstawowe: `J/K` + `Enter`; `T` otwiera Terminal, `F` otwiera Files.
Launcher reapuje zakończone dzieci i pozostaje nadzorowany przez PID1.

## Stabilność framebufferu

Zachowana zostaje zasada wprowadzona w 2.5.1: podczas aktywnej sesji Flux tylko
WindowManager renderuje do GOP framebuffer. Kernel/userspace logi są kierowane
do seriala i nie mogą przewijać ani nadpisywać pulpitu.

Dodatkowo persistent VFS reads przechodzą teraz przez 4 KiB kernel-owned bounce
buffer. Storage/FAT32 nie otrzymuje bezpośrednio userspace virtual address jako
bufora I/O; po zakończeniu I/O kernel kopiuje dane do zwalidowanego bufora
procesu. Zmiana jest ukierunkowana na błędy `CAT: READ FAILED` i
`VFS: READ FAILED` widoczne w aplikacjach Ring 3.

## Aplikacje

- Flux Terminal: `cat/read`, `which`, `run`, `gui`, `open`, jobs, wait,
  history, status i `home`;
- Files: quick access, VFS preview oraz uruchamianie GUI ELF;
- Monitor: heartbeat sesji i procesu;
- Settings: session-local Dark/Light Signal;
- About: informacje o 3.0 i architekturze systemu.

Aplikacje mają poprawione domyślne pozycje, żeby pojedynczo otwierały się w
centralnej przestrzeni roboczej zamiast odtwarzać układ pięciu nakładających się
okien z Developer Preview.

## Build na macOS

```bash
./scripts/build-macos.sh --configuration debug --rebuild
```

Development image:

```text
dist/KuroganeOS-3.0.0-macos-qemu.img
```

Pełny runtime acceptance wymaga uruchomienia tej konkretnej wersji w QEMU na
rzeczywistym Macu. Sam commit/release note nie jest dowodem runtime PASS.

## Znane ograniczenia

3.0 kończy etap desktop-session preview, ale nie kończy roadmapy:

- `libui` nadal używa compatibility `ku_ui_frame` transportu;
- publiczne VFS ABI nie ma jeszcze `readdir/stat/write/mkdir/...`;
- interactive resize, clipboard i pełny wheel routing pozostają do zrobienia;
- compositor/backbuffers/damage tracking są planowane na 3.2;
- instalowalny ISO na macOS pozostaje osobnym torem naprawy;
- brak GPU acceleration, audio, NVMe i multi-monitor.

Dalszy rozwój: `docs/roadmap/DESKTOP_ROADMAP.md`.
