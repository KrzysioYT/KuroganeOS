# KuroganeOS 3.1.0 — Red Flux Interaction Update

KuroganeOS 3.1.0 jest etapem stabilizacji interakcji i identyfikacji wizualnej
Kurogane Desktop. Wydanie koncentruje się na problemach widocznych podczas
rzeczywistego używania 3.0.x w QEMU: miganiu podczas drag/resize, tekście
wychodzącym poza okna, niespójnym sterowaniu oraz dwóch niezależnych
implementacjach shella.

## Red Flux

Domyślna paleta desktopu została przebudowana na własny profil KuroganeOS:

- prawie czarne tło;
- grafitowe powierzchnie;
- stalowo-szare granice i tekst pomocniczy;
- czerwony sygnał focus/active;
- jaśniejsza czerwień dla ostrzeżeń i akcji zamknięcia.

Stylistyka jest inspirowana czarno-czerwonym logo KuroganeOS, ale nie kopiuje
Windows, macOS ani środowisk linuksowych.

## Stabilny framebuffer

3.1 dodaje software backbuffer dla typowych trybów GOP do 1600x1200. Window
Manager buduje kompletną klatkę poza widocznym framebufferem, a następnie
kopiuje gotową klatkę do GOP. Jeżeli tryb przekracza pojemność backbuffera,
system zachowuje bezpieczny bezpośredni fallback.

Dzięki temu drag i resize nie powinny pokazywać użytkownikowi pośredniego stanu
`clear -> częściowy desktop -> kompletna klatka`.

## Clipping i skala tekstu

Każdy callback aplikacji GUI dostaje clip odpowiadający content area swojego
okna. Renderer nie może zapisać pikseli poza ten prostokąt. Window Manager
nakłada również limit skali tekstu zależny od szerokości content area:

- kompaktowe okna: body text 1x;
- szerokie/maximized surfaces: body text maksymalnie 2x;
- chrome i tytuły pozostają niezależne od limitu body.

To jest warstwa bezpieczeństwa layoutu przed późniejszym natywnym widget ABI.

## FluxShellCore

Fallback console shell oraz `/gui/terminal` używają od 3.1 wspólnego
`userspace/common/flux_shell.h`.

Wspólne są m.in.:

- `help`, `clear`, `version`, `uname`, `pid`, `whoami`, `status`;
- `history`, `jobs`, `wait`;
- `pwd`, `cd`, `cat`, `read`, `which`;
- `apps`, `run`, `open`, `gui`, `home`;
- `hello`, `external`, `files`, `monitor`, `about`;
- `echo`, `calc`, `sleep`, `yield`, `true`, `false`, `exit`;
- spójne komunikaty dla capability, których Ring-3 ABI jeszcze nie posiada.

GUI Terminal jest frontendem tego samego silnika, a nie osobnym parserem.

## Sterowanie

SDK otrzymuje nazwane kody klawiszy. Aplikacje nie używają już przypadkowych
wartości scancode jako `ku_ui_event.key`.

Podstawowy model:

- `Arrow Up/Down` — wybór/history;
- `Arrow Left/Right` — edycja kursora w Terminalu;
- `Home/End` — początek/koniec inputu;
- `Enter` — aktywacja/wykonanie;
- `Escape` — anulowanie/czyszczenie lokalnego inputu;
- `Tab` — przejście focusu tam, gdzie aplikacja ma wiele kontrolek;
- `J/K` pozostają opcjonalnymi aliasami, nie są główną instrukcją UI.

## Znane ograniczenia

3.1 nadal korzysta z compatibility `ku_ui_frame` jako transportu libui. Pełne
widget hit-testing, pointer IDs, directory `readdir/stat`, IPC services i
compositor damage regions pozostają kolejnymi etapami roadmapy.

Instalowalne ISO na macOS pozostaje osobnym torem naprawy; development IMG +
QEMU pozostaje podstawowym środowiskiem walidacji 3.1.
