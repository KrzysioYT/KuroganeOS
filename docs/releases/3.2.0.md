# KuroganeOS 3.2.0 — Red Flux Desktop Shell

KuroganeOS 3.2.0 rozwija 3.1 z developer-preview GUI w spójny desktop shell.
Najważniejsze zmiany dotyczą wejścia do systemu, docka, warstwy wizualnej i
własności sesji GUI.

## Normalny boot

Red Flux jest teraz domyślnym trybem UEFI. Nie trzeba już naciskać `D`, a
historyczny komunikat `DESKTOP ALPHA` został usunięty z loadera.

Okno wyboru podczas startu pozostawia tryby awaryjne:

- `S` / `F8` — Safe Mode;
- `X` — Diagnostics;
- `D` — natychmiastowe przejście do normalnego desktop boot.

Po przejęciu GOP przez kernel tekstowe testy pozostają na serialu, natomiast
framebuffer pokazuje Red Flux boot splash i rzeczywisty progres checkpointów:
paging, Ring-3 runtime, filesystem, storage, preemption i PID1. Safe Mode,
Diagnostics, Installer oraz fatalny błąd automatycznie przywracają tekstową
konsolę serwisową.

## Session Gate / Login

PID1 nie uruchamia już bezpośrednio Launchera. Nowy model to:

```text
/system/init (PID 1)
 -> /gui/login
 -> /gui/launcher (Red Flux Home)
 -> aplikacje sesji
```

`/gui/login` jest systemową powierzchnią bez zwykłego window chrome. Enter
otwiera lokalną sesję deweloperską i uruchamia Red Flux Home. Po zakończeniu
Home kontrola wraca do bramy sesji.

3.2 celowo nie udaje jeszcze uwierzytelniania hasłem. Prawdziwe konta,
credential store, blokada ekranu i hasła wymagają dedykowanej userspace account
service i są dalszym etapem.

## Pełnoprawny Dock

Dolny Pulse Ribbon został przebudowany w Red Flux Dock. Dock zawiera przypięte
systemowe pozycje:

- Home;
- Terminal;
- Files;
- Monitor;
- Settings;
- About.

Każda pozycja ma własną geometryczną ikonę, stan uruchomienia i stan focus.
Kliknięcie aktywnej aplikacji przywraca/focusuje istniejące okno. Kliknięcie
nieuruchomionej pozycji wysyła quick-launch do Home, które tworzy proces
aplikacji. Obok przypiętej sekcji pozostaje dynamiczna sekcja żywych okien do
focus/restore.

## Session ownership

GUI 3.2 nie jest już zbiorem anonimowych procesów uruchamianych przez Ring-0.
WindowManager zapamiętuje PID Red Flux Home i akceptuje nowe surfaces wyłącznie
od procesu Home lub jego potomków. Login jest osobnym dozwolonym systemowym
gatem.

Stare Ring-0 desktop surfaces są zachowane tylko jako kompatybilność dla
historycznego boot-host self-testu i nie biorą udziału w renderowaniu, focusie,
hit-testingu ani docku.

## Pulpit i grafika

Red Flux 3.2 rozwija czarno-grafitowo-czerwoną identyfikację wizualną:

- gradientowe prawie-czarne tło;
- duży, niski-kontrast geometryczny znak Kurogane w tle;
- nowy top identity rail;
- odświeżony window chrome i resize grip;
- osobne wizualne powierzchnie boot i login;
- geometryczne ikony docka bez zależności od assetów systemowych;
- software backbuffer z 3.1 pozostaje podstawą prezentacji bez tearingu/flickera.

## Build

macOS development IMG:

```bash
./scripts/build-macos.sh --configuration debug --rebuild
```

Wynik:

```text
dist/KuroganeOS-3.2.0-macos-qemu.img
```

## Walidacja

Zmiany zostały poddane auditowi kodu i zgodności ścieżek buildowych. Pełny
runtime PASS dla boot splash, loginu i interaktywnego docka wymaga uruchomienia
świeżego IMG w QEMU na docelowym macOS. Do czasu takiego testu release nie jest
opisywany jako runtime-verified.
