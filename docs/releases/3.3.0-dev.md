# KuroganeOS 3.3.0-dev — Dev Beta Media & Installer

KuroganeOS 3.3 jest oznaczone jako **DEV BETA**. To wydanie rozwojowe, a nie
stabilne wydanie produkcyjne. Głównym celem serii 3.3 jest zamiana osobnych
„development image” i „installer ISO” w jeden spójny model nośnika:

```text
KuroganeOS media (IMG albo ISO)
  -> Red Flux Setup
     -> Try KuroganeOS
     -> Install KuroganeOS
```

## Try KuroganeOS

`install.pkg` może zostać zamontowany przez kernel jako read-only live root.
Dzięki temu użytkownik może uruchomić regularny Ring-3 Login, Red Flux Home,
Terminal, Files, Monitor, Settings i About bez wcześniejszego instalowania
systemu na dysku.

Live root jest celowo tylko do odczytu. Zmiany wymagające trwałego zapisu nie są
obietnicą sesji live.

## Install KuroganeOS

Instalator wykorzystuje istniejący, kernelowy backend AHCI/GPT/FAT32. Surowe
partycjonowanie nie jest wystawiane jako userspace syscall.

Wizard 3.3 prowadzi przez:

1. wybór `Try` / `Install`;
2. wybór języka `English` / `Polski`;
3. utworzenie lokalnej nazwy użytkownika;
4. wybór konta bez hasła albo z hasłem;
5. wybór wykrytego dysku SATA/AHCI;
6. jawne wpisanie `INSTALL` przed pierwszym destrukcyjnym zapisem;
7. protective MBR + primary/backup GPT;
8. ESP FAT32 + Kurogane Root FAT32;
9. skopiowanie i sprawdzenie payloadu;
10. zapis konfiguracji języka i konta.

Instalacja tworzy m.in.:

```text
/etc/locale.cfg
/etc/user.cfg
/etc/first.run
```

Login zainstalowanego systemu czyta profil użytkownika i opcjonalnie wymaga
hasła. Brak hasła pozostawia szybkie wejście Enter/click.

### Ważne o haśle w DEV BETA

3.3-dev używa tymczasowego `FNV1A64-DEV` wyłącznie jako prostego verifiera
lokalnego profilu. **Nie jest to kryptograficzny KDF ani bezpieczny credential
store.** Nie należy używać hasła, które jest wykorzystywane gdziekolwiek indziej.
Docelowa account service ma zastąpić ten mechanizm przed stabilnym wydaniem.

## Media build

Od 3.3 preferowane są ujednolicone polecenia, które tworzą jednocześnie IMG i
ISO. Oba nośniki zawierają `install.pkg` i wchodzą do Red Flux Setup.

### Windows + WSL

Windows wymaga repozytoryjnego toolchainu z paczki:

https://drive.google.com/file/d/1sHfNdDOOVeJh3Q0FOtUlqPbHZIZ-ykEk/view?usp=sharing

Po wypakowaniu do głównego katalogu repozytorium:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-media.ps1 -Configuration release -Rebuild
```

### macOS

```bash
bash ./scripts/build-media-macos.sh --configuration release --rebuild
```

### Linux x86-64

```bash
bash ./scripts/setup-linux.sh --install
bash ./scripts/build-media-linux.sh --configuration release --rebuild
```

## Artefakty

W zależności od hosta powstaje jeden z IMG:

```text
dist/KuroganeOS-3.3.0-dev-windows-qemu.img
dist/KuroganeOS-3.3.0-dev-macos-qemu.img
dist/KuroganeOS-3.3.0-dev-linux-qemu.img
```

oraz wspólny instalacyjny/live ISO:

```text
dist/KuroganeOS-3.3.0-dev-x86_64.iso
dist/SHA256SUMS.txt
```

## Runtime acceptance

Kod i ścieżki build zostały przygotowane do testów, ale 3.3-dev nie jest
opisywane jako runtime-verified dopóki świeże media nie przejdą przynajmniej:

- boot IMG -> Try -> Login -> Home;
- boot ISO -> Try -> Login -> Home;
- Install -> EN profile bez hasła -> reboot z HDD -> Login;
- Install -> PL profile z hasłem -> reboot z HDD -> poprawne/niepoprawne hasło;
- anulowanie przed `INSTALL` bez zapisu tablicy partycji;
- instalacja na osobnym dysku SATA/AHCI i verification wszystkich plików;
- build media na Windows, macOS i Linux.

DEV BETA zachowuje Safe Mode i Diagnostics jako ścieżki serwisowe.
