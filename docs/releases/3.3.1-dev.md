# KuroganeOS 3.3.1-dev — VirtualBox Qualification & Enablement

Status: **DEV BETA**

3.3.1-dev koncentruje się na czterech obszarach:

1. powtarzalny boot ISO w x86-64 UEFI/VirtualBox;
2. referencyjny profil sprzętowy VM dla sieci i audio;
3. dokumentacja dla nowych użytkowników i programistów;
4. uczciwy fundament pod przyszłą kompatybilność grafiki/Direct3D.

## ISO / VirtualBox

Najważniejsza naprawa dotyczy EFI boot image w ISO.

Poprzedni builder używał 64 MiB FAT32 jako obrazu El Torito. 3.3.1 używa
**30 MiB FAT16**, czyli 61440 sektorów po 512 B. Dzięki temu obraz mieści się w
16-bitowym zakresie liczby sektorów El Torito EFI.

Nowy ISO layout:

```text
ISO9660/Joliet/Rock Ridge
  /boot.catalog
  /efiboot.img              FAT16 30 MiB
  /EFI/BOOT/BOOTX64.EFI
  /kernel.elf
  /install.pkg

El Torito EFI platform 0xEF
  -> /efiboot.img
       /EFI/BOOT/BOOTX64.EFI
       /EFI/BOOT/kernel.elf
       /kernel.elf
       /install.pkg

GPT
  -> EFI System Partition exposing the El Torito EFI image
```

`-isohybrid-gpt-basdat` został zastąpiony przez właściwy dla czysto-UEFI modelu
`-efi-boot-part --efi-boot-image`.

## Mandatory 20-pass verification

Każde ISO tworzone przez wspólny builder przechodzi automatycznie 20 passów.
Każdy pass sprawdza:

- niezmienny SHA-256 ISO;
- obecność El Torito;
- identyfikację entry jako EFI/UEFI;
- obecność GPT;
- obecność EFI System Partition w GPT;
- `/efiboot.img`;
- `/EFI/BOOT/BOOTX64.EFI`;
- `/kernel.elf`;
- `/install.pkg`;
- limit `<65535` sektorów EFI image;
- integralność FAT przez `fsck.fat`/`dosfsck`;
- pliki loader/kernel/package wewnątrz FAT;
- PE AMD64 loader (`MZ`, `PE`, `0x8664`, PE32+, EFI application);
- identyczność BOOTX64.EFI w ISO i wewnątrz EFI image.

Jeżeli dowolny pass zawiedzie, ISO nie jest publikowane do `dist/`.

## Networking

Istniejący driver E1000 dokładnie odpowiada referencyjnemu 82540EM VirtualBox.
Kernel ma Ethernet/ARP/IPv4/ICMP/UDP/DHCP/DNS oraz podstawowy TCP probe.

3.3.1 zmienia policy błędów: chwilowy brak DHCP/NAT nie może zabić całego bootu.
Jeżeli fizyczny interfejs nie może zostać skonfigurowany, kernel publikuje
loopback fallback i desktop może wystartować offline.

Publiczny Ring-3 socket/DNS ABI nie został na siłę zamrożony jako długi blocking
syscall. Docelowy service będzie asynchroniczny i oparty o handle/event model.

## Audio

Dodano minimalny sterownik Intel ICH AC'97:

```text
PCI ID        8086:2415
Output        PCM
Format        signed 16-bit little-endian
Channels      stereo
Rate          48000 Hz
DMA           bus-master, DMA32
```

Driver jest rejestrowany w centralnym driver managerze i automatycznie binduje
się do zgodnego urządzenia PCI.

Publiczny Ring-3 audio stream API nie jest jeszcze ukończony; 3.3.1 dostarcza
hardware backend, na którym bezpieczny async service będzie oparty.

## DirectX / Direct3D

3.3.1 **nie deklaruje fałszywie pełnego DirectX 11/12**.

Powstała dokumentacja architektury kompatybilności. Plan zakłada:

```text
Direct3D compatibility frontend
 -> Kurogane Graphics Runtime
    -> software backend
    -> future accelerated GPU backend
```

Pełna zgodność wymaga osobnego graphics runtime, zasobów, command submission,
shaderów i backendu GPU. Nie są dodawane puste funkcje D3D zwracające sukces.
