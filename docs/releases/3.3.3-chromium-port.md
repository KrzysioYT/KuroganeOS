# KuroganeOS 3.3.3-dev — Chromium browser port patch

This patch replaces the old monolithic Kurogane Web HTTP demo with a browser shell designed around Chromium `content_shell` ownership boundaries.

- Chromium upstream is pinned to `4137589c17766b2c0036332e00ad0d453e342a92`.
- `BrowserContext`, `NavigationController`, `PlatformDelegate` and bootstrap `RenderView` responsibilities are separated inside Kurogane Web.
- Plain HTTP navigation remains the temporary KuroganeOS network bridge while the Chromium socket/TLS platform is ported.
- HTTP redirects are followed with a bounded redirect limit.
- HTTPS redirects are reported explicitly as a missing TLS platform dependency rather than a generic HTTP failure.
- The browser displays E1000, DHCP, guest IPv4 and DNS state.
- `scripts/fetch-chromium.sh` and `scripts/fetch-chromium.ps1` fetch the exact upstream revision into the ignored `third_party/chromium/src/` workspace.
- Full Blink/V8 support is not claimed until the actual Chromium targets compile and run on KuroganeOS.

See `docs/CHROMIUM_PORT.md` for the port dependency order.
