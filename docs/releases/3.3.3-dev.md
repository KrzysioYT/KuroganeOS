# KuroganeOS 3.3.3-dev — Red Flux

Status: **QUALIFIED (scoped DEV milestone)**

This document is the consolidated milestone record for formal version `3.3.3-dev`. The historical `dev/3.3.5-*` through `dev/3.3.9-*` branches were internal Red Flux engineering workstreams and are folded into this milestone; they are not separate formal releases.

`QUALIFIED` here means the deliberately bounded Red Flux Definition of Done has verified implementation and automated runtime/regression evidence. It does not mean KuroganeOS is stable or that later Road-to-15 capabilities already exist.

## Qualified Red Flux scope

### Boot / UEFI

- native x86-64 UEFI boot path;
- GPT/ESP media generation;
- OVMF/QEMU boot qualification;
- Try/install media paths.

### Installer and persistence

- GPT/ESP/root installation flow;
- persistent FAT32 root;
- profile and locale persistence foundation;
- recoverable installer state replacement with staging/rollback/commit-marker semantics;
- production FAT32 integration regression;
- install package and media verification.

### Filesystem and Ring-3

- writable FAT32/VFS foundation;
- ELF64 Ring-3 process execution;
- syscall ABI and process ownership cleanup;
- bounded public file handles/read/write/seek/directory operations;
- named IPC, event and shared-memory primitives used by later service work.

### Networking

Red Flux networking scope includes:

`Ethernet -> ARP -> IPv4 -> DHCP -> DNS -> TCP -> HTTP/HTTPS`

Automated QEMU qualification covers the supported virtual NIC matrix used by the milestone, including E1000, PCnet and VirtIO-net paths.

### TLS / HTTPS

The final Red Flux milestone incorporates the later internal TLS workstream rather than the older initial 3.3.3 snapshot limitation. The qualified scope includes:

- entropy/RNG and CTR_DRBG foundation;
- Mbed TLS integration cleanup;
- SNI;
- X.509 chain validation and hostname validation;
- real guest TLS handshake;
- real HTTPS qualification with peer certificate validation enabled.

A future Connected Steel milestone still owns TLS 1.3 hardening, a broader CA/update model and network-security architecture.

### Desktop

- Red Flux login/session/desktop path;
- Home, launcher/dock and current core GUI applications;
- software-rendered window/compositor path;
- session-local desktop pinning and current telemetry applications.

The final Forge Desktop and Forge Design system are later milestones.

### Audio

Red Flux scope is the bounded AC'97 PCM foundation and current Ring-3 audio-facing primitives. Full async audio-service policy, mixer/capture/resampling and Intel HDA belong to later milestones and are not missing Red Flux work.

### Graphics

Red Flux scope is UEFI GOP scanout plus the real software compositor and display capability reporting. Hardware 3D command submission is intentionally not claimed. Forge Graphics owns buffers/textures/queues/shaders/software 3D and a real accelerated hardware backend.

Direct3D support is not claimed by Red Flux.

## Kurogane Web boundary

The Red Flux browser remains a bounded native browser/frontend, not Chromium. Later Connected Userspace and Platform/Web milestones own async socket APIs, broader userspace TLS/platform facilities, DOM/CSS/JS and browser-class security/runtime work.
