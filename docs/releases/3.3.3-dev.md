# KuroganeOS 3.3.3-dev — Desktop Performance & Web

Status: **DEV BETA**

## Desktop pinning

Red Flux now owns a session-local set of desktop application shortcuts.

- Home is always pinned and cannot be removed.
- Performance is pinned by default.
- Terminal, Files, Kurogane Web, System Monitor, Settings and About can be
  pinned or unpinned from Red Flux Home with `P`.
- A desktop shortcut and its Dock pin use the same activation path: an existing
  window is focused/restored; otherwise Home launches the application.

Pin persistence across reboot is intentionally not claimed yet. It will move to
the persistent settings service when that write-capability ABI is ready.

## Performance

`/gui/performance` starts automatically with the graphical session and the
WindowManager places it at the middle-right side of the workspace.

The live view exposes:

- CPU activity estimated from real scheduler switch/timer counters;
- RAM percentage and physical memory totals;
- disk activity from completed block-device reads/writes;
- GPU/GFX activity from Red Flux/GOP compositor submissions.

The current GPU value is **not a physical GPU-core utilization counter**. The
3.3.3 graphics path is still UEFI GOP scanout plus a software compositor, so the
UI explicitly labels this distinction.

## Kurogane Web

`/gui/browser` is the first KuroganeOS browser frontend connected to the native
network stack.

3.3.3 adds a bounded Ring-3 HTTP service over:

```text
E1000 -> Ethernet -> ARP -> IPv4 -> DHCP -> DNS A -> TCP -> HTTP/1.0 GET
```

The browser accepts `http://` URLs, resolves the host with the KuroganeOS DNS
client, downloads a bounded response and renders readable text from basic HTML.

### Important browser boundary

Kurogane Web 3.3.3 is **not Chromium yet**. Chromium requires a much larger
platform layer including asynchronous sockets, TLS, threads, filesystem APIs,
process sandbox integration, timers and a substantially broader libc/POSIX
surface. Shipping a tiny native browser and calling it Chromium would be
misleading.

HTTPS/TLS and a Chromium backend remain future work.

## Graphics / GPU / DirectX boundary

3.3.3 adds a PCI display-adapter capability probe. The system now distinguishes:

- a detected PCI display-class device;
- UEFI GOP scanout availability;
- Red Flux software compositor availability;
- accelerated 3D capability.

`accelerated_3d` remains false until a real hardware command-submission driver
exists.

Direct3D 9, 11 and 12 are **not marked complete**. A real implementation needs
resource objects, texture/buffer allocation, shader/runtime support, command
submission, synchronization, presentation and an accelerated backend. The
current work is the foundation for that stack, not a fake success shim.

## New public SDK surface

Append-only syscalls:

```text
18 KU_SYS_SYSTEM_SNAPSHOT
19 KU_SYS_DESKTOP_PIN
20 KU_SYS_NET_STATUS
21 KU_SYS_HTTP_GET
```

Headers:

```text
<kurogane/system.h>
<kurogane/desktop.h>
<kurogane/network.h>
```

HTTP is deliberately bounded to 4096 response bytes in this DEV BETA transport.
A general asynchronous socket service is still required before the networking
ABI can be considered browser-class.
