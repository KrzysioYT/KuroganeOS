# KuroganeOS 3.3.7-dev

Version: `3.3.7-dev`

Date: `2026-08-29`

## Summary

3.3.7-dev turns the existing TLS code into a real qualification target. A KuroganeOS guest now completes the production DNS -> TCP/443 -> entropy/CTR_DRBG -> Mbed TLS handshake -> SNI -> X.509/hostname/time validation -> HTTPS response path in the automated QEMU/OVMF E1000 qualification environment.

This does not close the release or the earlier Oracle VirtualBox gate. It records a real TLS foundation PASS for the tested environment only.

## Kernel changes

- TLS qualification uses the production networking/TLS stack rather than a host-side fake or compile-only probe.
- RTC snapshot handling was hardened against CMOS rollover/UIP races.
- A bounded monotonic wall-clock fallback derives short-term wall time from a previously validated hardware RTC snapshot and PIT ticks when a later raw CMOS snapshot transiently fails.
- Mbed TLS now retains the verified peer certificate after handshake so KuroganeOS can perform its explicit post-handshake validity-interval check.

## Driver changes

- RTC validates BCD/binary CMOS format, calendar fields, century handling and snapshot consistency.
- Monotonic fallback requires a real successful RTC snapshot and initialized PIT; it does not invent a timestamp.

## Userspace changes

No new stable userspace TLS ABI is claimed by this branch.

## Security changes

- Certificate validation remains fail-closed.
- Expiry/not-before checks were NOT disabled to obtain the PASS.
- Hostname verification and required CA verification remain in the real handshake path.
- `MBEDTLS_SSL_KEEP_PEER_CERTIFICATE` is enabled because KuroganeOS requires the verified peer certificate for its explicit post-handshake certificate-time check.
- SHA-1 remains rejected for non-root certificates; only the narrowly documented self-issued trust-anchor case is tolerated.

## Networking changes

- Dedicated CI drives a real HTTPS request to `www.google.com` through production DNS/TCP/TLS.
- TLS BIO uses bounded partial/retryable socket-like semantics.
- The trust store is parsed by Mbed TLS and the real peer certificate chain is checked.
