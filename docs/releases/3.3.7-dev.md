# KuroganeOS 3.3.7-dev

Version: `3.3.7-dev`

## Summary

3.3.7-dev turns the existing TLS code into a real qualification target. The release is explicitly NOT complete until a guest performs a real DNS -> TCP/443 -> Mbed TLS handshake -> SNI -> X.509/hostname/time validation -> HTTPS response path.

## Kernel changes

- TLS qualification uses the production networking/TLS stack rather than a host-side fake or compile-only probe.
- RTC snapshot handling was hardened against CMOS rollover/UIP races.
- A bounded monotonic wall-clock fallback now derives short-term wall time from a previously validated hardware RTC snapshot and PIT ticks when a later raw CMOS snapshot transiently fails.

## Driver changes

- RTC now validates BCD/binary CMOS format, calendar fields, century handling and snapshot consistency.
- Monotonic fallback requires a real successful RTC snapshot and an initialized PIT; it does not invent a timestamp.

## Userspace changes

No new userspace TLS ABI is claimed by this branch.

## Security changes

- Certificate validity checking remains fail-closed.
- Expiry/not-before checks have NOT been disabled to make tests pass.
- Hostname verification and required CA verification remain part of the real handshake path.
- SHA-1 remains rejected for non-root certificates; only the narrowly documented self-issued trust-anchor case is tolerated.

## Networking changes

- Dedicated CI drives a real HTTPS request to `www.google.com` through production DNS/TCP/TLS.
- TLS BIO follows bounded partial/retryable socket-like semantics.
- The trust store is parsed by Mbed TLS and the real peer certificate chain is checked.

## Graphics changes

No release-specific graphics change.

## Filesystem changes

Trust material is loaded through the production system path; no fake certificate backend is used.

## Application changes
