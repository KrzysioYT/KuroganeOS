# KuroganeOS 3.4.0-dev

- **Version:** 3.4.0-dev
- **Channel:** DEV
- **Release status:** STACKED DEVELOPMENT QUALIFIED / NOT RELEASED
- **Date:** 2026-08-29
- **Generation:** Red Flux services foundation

## Summary

3.4.0-dev begins the userspace service architecture without introducing a
parallel fake registry. The existing kernel named-IPC endpoint table remains
the source of truth for service names, PID ownership, generation-safe handles,
pending connections and process-exit cleanup. A public service-oriented SDK
surface exposes that real backend as service registration and discovery by
connection.

Formal sequential release state remains blocked at 3.3.4-dev pending real
Oracle VirtualBox host acceptance. This file describes stacked development and
is not a release tag.

## Kernel changes

No new kernel transport was required for the first 3.4.0 atom. Existing IPC
already provides bounded named endpoints and per-process ownership, and the
runtime releases IPC objects on process exit.

## Driver changes

None in this atom.

## Userspace changes

Added `sdk/include/kurogane/service.h` with typed service operations:

- `ku_service_register`
- `ku_service_connect`
- `ku_service_accept`
- `ku_service_send`
- `ku_service_receive`
- `ku_service_close`

The functions delegate directly to the existing real IPC syscall transport.
They do not return fabricated success and do not maintain duplicate service
state.

## Security changes

Service endpoint ownership continues to be enforced by existing IPC PID checks
and generation-safe handles. Process exit continues to invoke IPC resource
release.

## ABI changes

No syscall number or ABI version is changed in this atom. The service API is a
typed source-level layer over existing public IPC syscalls. ABI regression tests
lock service handle/message types and capacities to the underlying IPC ABI.
